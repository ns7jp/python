# python 🐍 Python基礎演習案件パック

**未経験からサーバー構築エンジニア(インフラエンジニア)を目指すための、実践型ポートフォリオ**

---

## 📌 このリポジトリについて

このリポジトリは、プログラミング未経験からサーバー構築エンジニア(インフラエンジニア)への転職・就職を目指す学習者のために作った、**Python基礎の演習パック**です。

ただの文法学習で終わらせず、

- ディスク使用率やメモリ使用率の計算
- ログファイルの読み書きと整理
- 外部コマンドの実行(subprocess)
- ポート疎通確認・HTTP監視
- 設定ファイル管理(JSON / ini / 環境変数)
- 例外処理・ロギングによる安全な運用
- pytestによる自動テスト

といった、**実際のサーバー運用・自動化の現場で使う題材**を通してPythonの基礎を身につけられるように設計しています。最終章では、これまで学んだ内容をすべて組み合わせた「ミニ・サーバー監視ツール」を自分の手で完成させます。

> 独学でつまずきやすいポイントには、なるべく丁寧に解説を入れています。「なぜこれを学ぶのか」を常にサーバーエンジニアの仕事と結びつけて説明することを意識しました。

## 🎯 対象読者

- プログラミング未経験〜初級者で、サーバー構築エンジニア(インフラエンジニア)を目指している方
- Pythonの文法は知っているが、実務でどう使うのかイメージが湧かない方
- 独学で学んでいて、自分の実装が合っているか自動で確認したい方

## ✨ この演習パックの特徴

1. **全11章、各章が「レッスン → サンプル → 演習 → 自動テストで答え合わせ → 模範解答」の流れで統一**されています。
2. **すべての演習に `pytest` によるテストが付属**しています。`exercises/` 配下のファイルを実装してからテストを実行すると、自分の実装が正しいかその場で確認できます(実装前はテストが失敗するのが正しい状態です)。
3. **すべてサーバーエンジニアの実務を意識した題材**(ディスク使用率、ログ管理、疎通確認、設定管理、監視ツールなど)です。
4. **外部ネットワークに依存しません**。ポートやHTTP通信が絡む演習も、すべてlocalhost上のダミーサーバーやモック(擬似的な代役)で完結するため、オフラインでも安心して取り組めます。
5. 最終章(第11章)は、**これまでの学習内容を統合したミニ・サーバー監視ツール**という集大成の題材です。

## 📖 各章の進め方

各章のディレクトリ(`modules/章番号_章名/`)は、以下の構成になっています(第10章のみ一部構成が異なります。詳細はその章のREADME.mdを参照してください)。

```
modules/01_python_kiso/
├── README.md        … この章のレッスン本文(学習目標・解説・演習問題)
├── examples/
│   └── example.py    … 動作するサンプルコード
├── exercises/
│   └── exerciseN.py  … 演習の雛形(ここを自分で実装する)
├── solutions/
│   └── exerciseN.py  … 模範解答
└── tests/
    └── test_exerciseN.py … 自動テスト(自己採点用)
```

進め方は次の通りです。

1. `modules/章番号_章名/README.md` を読み、その章で学ぶ内容を理解する。
2. `examples/example.py` を実行し、実際に動くコードのイメージをつかむ。

   ```bash
   python3 modules/01_python_kiso/examples/example.py
   ```

3. `exercises/exerciseN.py` を開き、`TODO` コメントと `NotImplementedError` の部分を自分で実装する。
4. 実装できたら、その章のテストを実行して確認する。

   ```bash
   pytest modules/01_python_kiso/tests
   ```

   すべて緑色(`passed`)になれば正解です。赤色(`failed`)になったら、エラーメッセージを読んで実装を見直しましょう。
5. どうしても分からないときは `solutions/exerciseN.py` の模範解答を確認する(ただし、まずは自分の力で書いてみることを強くおすすめします)。

リポジトリ全体のテストを一度にまとめて実行することもできます。

```bash
pytest modules/
```

> ⚠️ 演習をまだ解いていない状態(初期状態)では、`exercises/` が未実装のためテストは失敗します。これは**正しい初期状態**です。各章を進めるごとに、対応するテストが緑色に変わっていくのを確認しながら学習を進めてください。

## 💡 このパックで意識した設計

サーバー構築エンジニアとして働くうえで大切だと考えている、次のような考え方を演習の随所に盛り込んでいます。

- **設定と処理を分離する**(09章): 値をハードコードせず、設定ファイルや環境変数から読み込む。
- **失敗を握りつぶさず、ログに残す**(06章): `try/except` で異常終了を防ぎつつ、`logging` で後から追跡できるようにする。
- **外部依存はモックしてテストする**(08章・11章): 実際のネットワーク通信に依存せず、依存性注入やモックでテスト可能な設計にする。
- **1回の失敗で騒がず、連続失敗で判断する**(11章): 誤報を減らすための、実践的な監視のしきい値設計。
- **自動テストで品質を担保する**(10章): 手作業の確認に頼らず、`pytest` で継続的に動作を確認できるようにする。
