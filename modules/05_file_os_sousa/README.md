## 1. 📘 この章で学ぶこと

この章では、Pythonで「ファイル」と「ディレクトリ(フォルダ)」を扱うための
基本を学びます。

- **open()とwith文**: ファイルを安全に開いて、使い終わったら確実に閉じる書き方
- **ファイルの読み書きモード**: `"r"`(読み込み)・`"w"`(書き込み・上書き)・
  `"a"`(追記)という、目的に応じたファイルの開き方の違い
- **pathlib.Path**: ファイルパス(場所を表す文字列)を、便利なメソッドを
  持ったオブジェクトとして扱う現代的な書き方
- **ディレクトリ内のファイル一覧取得**: `Path.iterdir()` や `Path.glob()` を
  使って、あるフォルダの中に何があるかを調べる方法
- **ファイルサイズや更新日時の取得**: `Path.stat()` を使って、ファイルの
  大きさ(バイト数)や最後に変更された日時を調べる方法

これらは、「ログファイルを読み書きする」「たまったログの中から
問題のある行を探す」「古いログファイルを整理する」といった、
サーバー運用の定番作業を自動化するための土台になります。

## 2. 🖥 サーバーエンジニアにとってなぜ重要か

サーバー構築エンジニア(インフラエンジニア)の日常業務には、
「ファイルを扱う」場面が驚くほどたくさんあります。

- **ログファイルの読み書き**: サーバーやアプリケーションは、動作の記録を
  ログファイルに書き残します。障害が起きたときは、まずログファイルを
  開いて「いつ、何が起きたか」を確認するのが基本の調査手順です。
  自動化スクリプトで独自のログを書き出す場面もよくあります。
- **エラー行の抽出**: 大量のログの中から `"ERROR"` を含む行だけを
  すばやく取り出せると、障害調査のスピードが大きく変わります。
  この作業はコマンドラインの `grep` に相当しますが、Pythonで実装できると
  条件を柔軟に組み合わせたり、他の処理と連携させたりできます。
- **古いログファイルの整理(ログローテーション)**: ログはためすぎると
  ディスク容量を圧迫し、最悪の場合サーバーが停止してしまいます。
  「新しいログは残しつつ、古いログを削除・アーカイブする」という
  ログローテーションの仕組みは、運用スクリプトの定番テーマです。
- **設定ファイルの読み込み**: サーバーの設定は、テキストファイルとして
  管理されることがよくあります。ファイルを正しく開き、内容を読み込む力は、
  設定を自動でチェック・生成するスクリプトを書くための基礎になります。

つまりこの章の内容は、**「ファイルとディレクトリを、安全かつ正確に
読み書きする力」**を養うものです。ここが身につくと、ログ監視ツールや
簡易的な運用自動化スクリプトを自分の手で書けるようになります。

## 3. 📖 解説

### 3.1 open()とwith文

`open()` はファイルを開くための組み込み関数です。ファイルを開いたら、
使い終わったあとに必ず `close()` で閉じる必要がありますが、手動で
`close()` を呼び出す書き方は、途中でエラーが起きると `close()` が
呼ばれずファイルが開きっぱなしになってしまう危険があります。

そこで使うのが **with文** です。with文を使うと、ブロックの処理が
終わったとき(エラーが起きたときも含む)に、自動的にファイルが
閉じられます。ファイルを扱うときは、基本的に常にwith文を使うと
覚えておきましょう。

```python
with open("app.log", "r", encoding="utf-8") as f:
    content = f.read()   # ファイルの中身をすべて文字列として読み込む
# withブロックを抜けた時点で、fは自動的に閉じられている
```

`encoding="utf-8"` は文字コード(文字をどのようにデータへ変換するかの
決まりごと)を明示的に指定しています。日本語を含むファイルを扱うときは、
文字化けを防ぐために `encoding="utf-8"` を指定する習慣をつけましょう。

### 3.2 ファイルの読み書きモード

`open()` の第2引数には「モード」を指定します。目的に応じて、
主に次の3つを使い分けます。

| モード | 意味 | ファイルがない場合 | 既存の内容 |
|---|---|---|---|
| `"r"` | 読み込み専用(read) | エラーになる | そのまま(変更しない) |
| `"w"` | 書き込み・上書き(write) | 新規作成される | **すべて消えて空になる** |
| `"a"` | 追記(append) | 新規作成される | 残ったまま、末尾に追加される |

```python
# "w": 新規作成 or 上書き。設定ファイルを作り直すときなどに使う
with open("config.txt", "w", encoding="utf-8") as f:
    f.write("debug = true\n")

# "a": 追記。ログファイルへの書き込みで最もよく使われるモード
with open("app.log", "a", encoding="utf-8") as f:
    f.write("[INFO] リクエストを受け付けました\n")

# "r": 読み込み専用
with open("app.log", "r", encoding="utf-8") as f:
    for line in f:            # ファイルは1行ずつforループで読める
        print(line.rstrip())  # rstrip()で末尾の改行を取り除いて表示
```

**"w"モードで開くと、既存の内容がすべて消えてしまう**点には特に注意が
必要です。ログファイルのように「過去の記録を残しておきたい」ファイルには、
必ず `"a"`(追記)モードを使いましょう。

ファイルの中身をまとめて読み込む方法もいくつかあります。

```python
with open("app.log", "r", encoding="utf-8") as f:
    text = f.read()            # ファイル全体を1つの文字列として読み込む
    # または
    lines = f.readlines()      # 1行ずつ、改行付きの文字列のリストとして読み込む
```

### 3.3 pathlib.Path

Python標準ライブラリの `pathlib` モジュールを使うと、ファイルパスを
「文字列」ではなく「Pathオブジェクト」として扱えます。OSによる
パスの区切り文字の違い(Windowsなら `\`、Linux/macOSなら `/`)を
気にせずに済むほか、パスに関する便利なメソッドが多数用意されています。

```python
from pathlib import Path

log_path = Path("/var/log") / "app" / "error.log"  # "/" 演算子でパスを連結
print(log_path)          # /var/log/app/error.log
print(log_path.name)     # "error.log"       (ファイル名)
print(log_path.suffix)   # ".log"            (拡張子)
print(log_path.parent)   # /var/log/app      (親ディレクトリ)
print(log_path.exists()) # True/False        (実際に存在するかどうか)
```

`Path` オブジェクトは `open()` の第1引数にそのまま渡すこともできますし、
`read_text()` / `write_text()` を使えば `open()` を書かずに
手軽にファイルの読み書きができます。

```python
log_path.write_text("[INFO] 起動しました\n", encoding="utf-8")  # 上書き書き込み
content = log_path.read_text(encoding="utf-8")                    # 読み込み
```

### 3.4 ディレクトリ内のファイル一覧取得

`Path.iterdir()` を使うと、あるディレクトリの直下にある
ファイルやサブディレクトリを1つずつ取り出せます。

```python
log_dir = Path("/var/log/app")
for entry in log_dir.iterdir():
    print(entry.name, "ディレクトリ" if entry.is_dir() else "ファイル")
```

「特定のパターンに合うファイルだけがほしい」場合は `Path.glob()` が
便利です。`*` は「任意の文字列」を意味するワイルドカードです。

```python
log_files = list(log_dir.glob("*.log"))  # 拡張子が.logのファイルだけを取得
```

`iterdir()` も `glob("*")` も**直下のファイル・ディレクトリだけ**が
対象です。サブディレクトリの中身まで再帰的に調べたい場合は
`glob("**/*.log")` のように `**` を使います(この章の演習では、
直下だけを対象にする基本形を扱います)。

### 3.5 ファイルサイズや更新日時の取得

`Path.stat()` を呼び出すと、ファイルの詳細情報(サイズや日時など)を
まとめて取得できます。

```python
info = log_path.stat()
print(info.st_size)   # ファイルサイズ(バイト単位の整数)
print(info.st_mtime)  # 最終更新日時(エポック秒 = 1970年からの経過秒数、float)
```

`st_mtime` はそのままだと人間には読みにくい数値なので、
`datetime.fromtimestamp()` を使って日時に変換すると分かりやすくなります。

```python
from datetime import datetime

updated_at = datetime.fromtimestamp(info.st_mtime)
print(updated_at)  # 例: 2026-09-01 10:00:00
```

「ファイルサイズが大きい順に並べる」「更新日時が古い順に並べる」といった
処理は、`sorted()` の `key` 引数(第3章で学んだ書き方)と組み合わせて
実現できます。この考え方は、この章の演習3・演習4でそのまま使います。

  - リスト内包表記(第3章)を使うと1行で実装できます。

### 演習3: `list_log_files_with_size(dir_path)` — 難易度: ★★☆

- **ファイル**: `exercises/exercise3.py`
- **目的**: `pathlib.Path` を使ったディレクトリの走査と、`stat()` による
  ファイルサイズの取得、`sorted()` による並べ替えを組み合わせる力を身につけます。
- **やること**: 指定ディレクトリ直下にある拡張子 `.log` のファイルについて、
  `(ファイル名, サイズ)` のタプルのリストを、サイズの降順で返す関数を実装します。
- **ヒント**:
  - `Path(dir_path).iterdir()` でディレクトリ直下のエントリを1つずつ
    取り出せます。
  - `entry.is_file()` と `entry.suffix == ".log"` を組み合わせて、
    「.logファイルだけ」を判定しましょう。
  - サイズは `entry.stat().st_size` で取得できます。
  - 並べ替えは `sorted(リスト, key=lambda item: item[1], reverse=True)`
    のように、タプルの2番目の要素(サイズ)を基準にします(第3章で
    学んだ `sorted()` の `key` 引数の応用です)。

### 演習4(応用): `find_old_log_candidates(dir_path, max_files_to_keep)` — 難易度: ★★★

- **ファイル**: `exercises/exercise4.py`
- **目的**: ログローテーション(古いログの整理)の考え方を、実際のコードとして
  実装する力を身につけます。あわせて「実際に破壊的な操作(削除)は行わず、
  候補を一覧するだけにとどめる」という安全設計の考え方も学びます。
- **やること**: 指定ディレクトリ直下の `.log` ファイルを更新日時
  (`st_mtime`)の新しい順に並べ、上位 `max_files_to_keep` 件を除いた
  「削除候補」のファイル名のリストを返す関数を実装します。
  **この関数は削除候補を一覧するだけで、実際にファイルを削除する処理
  (`os.remove()` など)は絶対に行わないこと**に注意してください。
- **ヒント**:
  - 演習3と同様に、まず `.log` ファイルだけを集めたリストを作ります。
  - `sorted(リスト, key=lambda entry: entry.stat().st_mtime, reverse=True)`
    で更新日時の新しい順に並べ替えます。
  - スライス `[max_files_to_keep:]`(第3章)を使うと、「先頭の
    `max_files_to_keep` 件を除いた残り」を簡単に取り出せます。
  - 最後に、各エントリの `.name` だけを集めたリストを作って返しましょう。
