# 第9章 設定ファイル管理(JSON / ini / 環境変数)

サーバーの「設定」をどこに、どうやって置くか。地味に見えて、実はサーバーエンジニアの仕事の土台になる、とても大事なテーマです。この章では、Pythonの標準ライブラリを使って設定ファイル(JSON・ini)を読み書きしたり、環境変数を扱ったりする方法を、手を動かしながら身につけていきます。焦らず一つずつ進めていきましょう。💪

---

## 1. 📘 この章で学ぶこと

- `json` 標準ライブラリを使って、JSON形式の設定ファイルを読み込む方法
- `configparser` 標準ライブラリを使って、ini形式の設定ファイルを読み書きする方法
- `os.environ` / `os.getenv` を使って環境変数を取得する考え方
- 「環境変数 → 設定ファイル → デフォルト値」という優先順位で設定値をマージ(統合)する方法
- 開発環境(dev)・ステージング環境(staging)・本番環境(prod)など、複数の環境向けに設定を切り替える考え方
- (参考程度に)PyYAMLを使ったYAML形式の設定ファイルの読み込み

どれも「設定をコードの外に出して管理する」という一つの大きなテーマにつながっています。1つずつ順番に理解していけば大丈夫です。🙆

## 2. 🖥 サーバーエンジニアにとってなぜ重要か

サーバー構築・運用の現場では、**同じプログラムを複数の環境(開発・検証・本番など)で動かす**のが当たり前です。そのとき、ポート番号やデータベースの接続先、ログの出力レベルなどが環境ごとに違っていても、プログラムのソースコード自体は変更したくありません。

そこで登場するのが「設定ファイル」と「環境変数」です。

- **設定はハードコード(コードに直接書き込むこと)しない**
  - 例えば `PORT = 8080` のようにソースコードの中に直接値を書いてしまうと、環境ごとにコードを書き換える必要が出てしまい、ミスの原因になります。設定ファイルや環境変数から読み込むようにしておけば、コードは1つのままで、設定だけを環境ごとに切り替えられます。

- **機密情報(パスワードやAPIキーなど)はソースコードに書かない**
  - データベースのパスワードやAPIキーをソースコードに直接書いてしまうと、そのコードをGitなどのバージョン管理システムにアップロードした瞬間に、誰でも見られる状態になってしまいます。これは重大なセキュリティ事故につながります。実際の現場では、機密情報は**環境変数**や、Gitの管理対象から外した専用の設定ファイル(`.env` ファイルなど)、あるいはクラウドの「シークレット管理サービス」といった仕組みを使って管理するのが基本です。

- **サーバー構築でよく出会う設定ファイル形式**
  - Webサーバーの `nginx.conf`、PythonアプリのDjango/Flaskの設定、SSHの `sshd_config`、systemdのユニットファイルなど、サーバー関連のソフトウェアは非常に多くの設定ファイルを扱います。JSONやiniのような形式に慣れておくことは、これらの設定ファイルを読み書きする力に直結します。

「設定を外に出す」「機密情報を直書きしない」という考え方は、この章で学ぶ技術だけでなく、サーバーエンジニアとしての基本姿勢そのものです。ぜひここでしっかり身につけてください。🔐

## 3. 📖 解説

### 3-1. JSON設定ファイルを読み込む(`json` 標準ライブラリ)

JSON(JavaScript Object Notation)は、`{}` と `[]` を使ってデータを表す、非常によく使われるデータ形式です。Pythonの辞書(dict)とほぼ同じ形をしているので扱いやすいのが特徴です。

```python
import json

with open("config.json", "r", encoding="utf-8") as f:
    config = json.load(f)  # ファイルオブジェクトから直接読み込む

print(config["port"])
```

- `json.load(f)`: **開いたファイルオブジェクト**からJSONを読み込み、dictやlistに変換する
- `json.loads(text)`: **文字列**からJSONを読み込む(ファイルではなく文字列の場合はこちら)
- `json.dump(data, f)`: dictなどのデータをファイルにJSON形式で書き込む
- `json.dumps(data)`: dictなどのデータをJSON形式の文字列に変換する

ファイルが存在しない場合にエラーで落ちてしまうと不便なことが多いため、`os.path.exists()` で事前に存在確認をしてから読み込む、というパターンもよく使います。

### 3-2. iniファイルの読み書き(`configparser` 標準ライブラリ)

iniファイルは `[セクション名]` の下に `キー = 値` を並べる形式で、古くからある設定ファイルの形式です。多くのサーバーソフトウェアで今も使われています。

```ini
[server]
host = 0.0.0.0
port = 8080

[database]
name = sampledb
user = app_user
```

Pythonでは `configparser` モジュールを使って読み書きします。

```python
import configparser

parser = configparser.ConfigParser()
parser.read("server.ini", encoding="utf-8")

print(parser.sections())               # ['server', 'database']
print(parser["server"]["port"])         # '8080' (常に文字列で返る点に注意)
print(dict(parser.items("server")))     # {'host': '0.0.0.0', 'port': '8080'}
```

**注意点**: `configparser` はすべての値を文字列(str)として扱います。ポート番号のような数値を使いたい場合は、自分で `int()` などを使って変換する必要があります。

書き込みも同じように行えます。

```python
writer = configparser.ConfigParser()
writer["server"] = {"host": "0.0.0.0", "port": "8080"}

with open("server.ini", "w", encoding="utf-8") as f:
    writer.write(f)
```

### 3-3. 環境変数(`os.environ` / `os.getenv`)

環境変数は、OS(オペレーティングシステム)が管理している「プログラムの外側」にあるキーと値のペアです。サーバーを起動するシェルスクリプトやDockerコンテナの設定などから渡されることが多く、設定ファイルよりもさらに「コードの外側」にある存在といえます。

```python
import os

# 方法1: os.environ は辞書のようなオブジェクト
port = os.environ["PORT"]          # 存在しないキーだとKeyErrorになる
port = os.environ.get("PORT")       # 存在しないと None が返る(安全)

# 方法2: os.getenv はより簡単にデフォルト値を指定できる
port = os.getenv("PORT")            # 存在しないと None
port = os.getenv("PORT", "8000")    # 存在しないと "8000"(デフォルト値)
```

サーバー運用の現場では、`os.getenv(キー, デフォルト値)` の形で、環境変数が設定されていなくてもプログラムが動くようにしておく書き方が好まれます。

### 3-4. 環境変数・設定ファイル・デフォルト値の優先順位マージ

実際のアプリケーションでは、1つの設定項目に対して複数の「情報源」が存在することがよくあります。

1. **環境変数**(最優先。サーバー起動時に指定されることが多い)
2. **設定ファイル**(環境変数が無い場合に使う)
3. **プログラム内のデフォルト値**(どちらも無い場合の最後の砦)

```python
def resolve_setting(key, env, config, default):
    if key in env:
        return env[key]
    if key in config:
        return config[key]
    return default
```

このように優先順位を明確に決めておくことで、「普段は設定ファイルの値を使うが、本番だけ環境変数で一時的に上書きしたい」といった柔軟な運用が可能になります。

### 3-5. 複数環境(dev / staging / prod)向け設定の切り替え

開発環境・ステージング環境(本番に近い検証環境)・本番環境で、設定の一部だけを変えたい、という場面もよくあります。その際は「共通設定(base)」と「環境ごとの差分設定(overrides)」を分けて管理し、実行時にマージ(統合)するという方法がよく使われます。

```python
base_config = {"debug": True, "log_level": "INFO", "worker_count": 1}

overrides = {
    "prod": {"debug": False, "log_level": "WARNING", "worker_count": 4},
}

def build_environment_config(env_name, base_config, overrides):
    merged = dict(base_config)          # base_config自体は変更しない
    if env_name in overrides:
        merged.update(overrides[env_name])
    return merged
```

ここでの「マージ」は**浅いマージ**、つまりトップレベルのキーだけを上書きするシンプルな方式です(辞書の中の辞書まで再帰的にマージする「深いマージ」はもっと複雑になるため、この章では扱いません)。

### 3-6. (参考)PyYAMLでYAML形式の設定を読み込む

YAML(ヤムル)は、インデント(字下げ)で構造を表す設定ファイル形式で、JSONよりも人間が読み書きしやすいとされ、Docker ComposeやKubernetes、CI/CD設定ファイルなどで非常によく使われています。Python標準ライブラリには含まれていませんが、`pyyaml` パッケージを使うと簡単に扱えます。

```python
import yaml

with open("config.yaml", "r", encoding="utf-8") as f:
    config = yaml.safe_load(f)

print(config["server"]["port"])
```

`yaml.safe_load()` を使うと、JSONの `json.load()` と同じ感覚でYAMLファイルを読み込めます。この章の演習では必須ではありませんが、サンプルコードで軽く触れているので、余裕があれば動かしてみてください。

## 4. 💻 サンプルコードの説明

`examples/example.py` では、この章で学んだ内容を1つのスクリプトにまとめて動かせるようにしています。実行すると、以下の流れで処理が進みます。

1. **JSON設定ファイルの読み込み**: 一時ディレクトリにサンプルのJSONファイルを作成し、`json.load()` で読み込んで内容を表示します。存在しないファイルを想定した場合の挙動も確認します。
2. **iniファイルの読み書き**: `configparser` でサンプルのiniファイルを書き込み、続けて読み込んで `{セクション: {キー: 値}}` の形の辞書に変換します。
3. **環境変数の基本**: `os.environ` にデモ用の値を一時的に設定し、`os.getenv()` で取得する様子を確認します(存在する場合・存在しない場合・デフォルト値つきの場合、それぞれを試します)。
4. **優先順位マージ**: 環境変数を模した辞書・設定ファイルを模した辞書・デフォルト値から、優先順位に従って1つの値を決定する処理を確認します。
5. **複数環境向け設定の切り替え**: `dev` / `staging` / `prod` それぞれの設定がどのようにマージされるかを表示します。
6. **(参考)PyYAMLでのYAML読み込み**: `pyyaml` がインストールされていればYAML文字列を読み込んで表示します(インストールされていなければスキップされます)。
7. **機密情報の扱い方**: 環境変数からパスワードを取得する例と、値をそのまま表示せずマスクする(伏せ字にする)工夫を紹介します。

このスクリプトはネットワークには一切アクセスせず、サンプルファイルはすべて一時ディレクトリ(`tempfile.TemporaryDirectory`)の中に作成・削除されるので、リポジトリを汚しません。安心して何度でも実行してみてください。

実行方法:

```bash

python3 modules/09_settei_kanri/examples/example.py
```

## 7. 🚀 発展課題

余裕がある方は、以下の課題にもチャレンジしてみてください。

1. **数値への型変換**: `load_ini_config` で読み込んだ値はすべて文字列になります。ポート番号などを想定して、`"8080"` のような文字列を `int()` で数値に変換するユーティリティ関数を自分で書いてみましょう。数値に変換できない値が来た場合の例外処理(`try`/`except ValueError`)も考えてみると、より実践的です。

2. **深いマージへの挑戦**: 演習4では「浅いマージ」(トップレベルのキーだけ上書き)を扱いましたが、ネストした辞書の中身まで再帰的にマージする「深いマージ」を行う関数を自分で実装してみましょう。（ヒント: 値が辞書型である場合は再帰的に自分自身の関数を呼び出す、という考え方がポイントです)

3. **`.env` 形式のファイルを読み込む**: `KEY=VALUE` の形式で1行ずつ書かれた `.env` ファイル(多くのフレームワークで使われる、環境変数をまとめて書くための簡易ファイル)を自作で読み込み、辞書に変換する関数を作ってみましょう。外部ライブラリを使わず、`str.split("=", 1)` などの文字列操作だけで実装できます。

4. **YAML設定ファイルとの相互変換**: PyYAMLを使って、JSON形式の設定ファイルをYAML形式に変換するスクリプトを書いてみましょう(`json.load()` で読み込んで `yaml.safe_dump()` で書き出す、という流れです)。
