# 第4章: 関数とモジュール分割

## 1. 📘 この章で学ぶこと

これまでの章では、1つのファイルの中に処理を順番に書いてきました。しかし、
プログラムが長くなってくると、同じような処理をあちこちにコピー&ペーストしたり、
1つのファイルがどんどん巨大になってしまったりします。

この章では、そうした問題を解決する2つの考え方を学びます。

- **関数(def)**: ひとまとまりの処理に名前を付けて、何度でも呼び出せるようにする仕組み
- **モジュール分割**: 関数をファイル単位で分けて整理し、必要なところでimportして使う仕組み

具体的には、次のトピックを扱います。

- `def` による関数の定義と、呼び出し方
- 位置引数・デフォルト引数・可変長引数(`*args`)
- 戻り値(`return`)
- docstring(関数の説明文)の書き方
- 複数ファイルへのモジュール分割と `import`
- デコレーターの基礎(関数に処理を「かぶせる」仕組み)

「関数」も「モジュール」も、最初は少し難しく感じるかもしれません。ですが、
一度コツをつかめば、プログラムがぐっと整理されて読みやすくなります。焦らず、
一歩ずつ進めていきましょう。💪

## 2. 🖥 サーバーエンジニアにとってなぜ重要か

サーバー構築・運用の現場では、監視スクリプトやログ集計ツール、バックアップの
自動化スクリプトなど、「同じような処理を繰り返し使う」場面がとても多くあります。

もし関数に分けずに同じ処理をあちこちにコピーしていると、こんな困りごとが
起こります。

- 仕様変更があったとき、コピーした箇所すべてを1つずつ直さなければならない(直し忘れが事故につながる)
- どこで何をしているのか把握しづらく、他の人(未来の自分も含む)が読みにくい
- テスト(動作確認)がしづらい

処理を**関数として切り出す**ことで、「1箇所を直せば全部直る」「関数単体で
テストできる」状態を作れます。これは、監視スクリプトや自動化ツールを
長く安全に運用していくうえで欠かせない考え方です。

さらに、関数を**モジュール(ファイル)単位で分割**しておくと、
「サーバー情報を扱う処理は `server_utils.py` に」「ログ処理は `log_utils.py` に」
といった形で役割ごとに整理でき、チームで開発するときにも作業がぶつかりにくく
なります。実際の運用ツールやWebアプリケーションのソースコードも、
ほとんどがこのようにファイルを分けて構成されています。

また、この章で扱う**デコレーター**は、「処理の前後に共通の処理を挟み込む」
仕組みです。たとえば「この処理にどれくらい時間がかかったかを毎回ログに残したい」
「実行前に必ず認証チェックをしたい」といった場面で使われます。サーバー運用の
現場でも、処理時間の計測やリトライ処理などにデコレーターの考え方がよく登場します。

## 3. 📖 解説

### 3.1 関数の基本(def, 引数, 戻り値)

関数は `def` というキーワードで定義します。

```python
def add(a, b):
    """2つの数値を足し算して返す。"""
    return a + b

result = add(3, 5)  # result は 8
```

- `def 関数名(引数, ...):` の形で定義する
- 関数の中で `return 値` と書くと、その値が呼び出し元に返される(**戻り値**)
- `return` がない、または `return` だけの関数は、`None` を返す

### 3.2 docstring(関数の説明文)

関数定義の直後に文字列(`"""..."""`)を書くと、それが**docstring**として
その関数に紐づきます。docstringには、その関数が「何をするか」「引数・戻り値は
何か」を書いておくのが良い習慣です。

```python
def celsius_to_fahrenheit(celsius):
    """セ氏温度を華氏温度に変換して返す。

    引数:
        celsius (float): セ氏温度。

    戻り値:
        float: 華氏温度。
    """
    return celsius * 9 / 5 + 32
```

docstringを書いておくと、他の人(未来の自分も含む)がその関数を読んだときに、
中身のコードを全部読まなくても使い方がわかるようになります。

### 3.3 位置引数・デフォルト引数

関数の引数には、大きく分けて次のような種類があります。

```python
def greet(name, role="オペレーター"):
    return f"こんにちは、{name}さん({role})!"

greet("田中")                     # role は省略 -> "オペレーター" が使われる
greet("鈴木", role="新人エンジニア")  # role を指定
```

- `name` のように、呼び出し時に必ず値を渡す必要がある引数を**位置引数**と呼ぶ
- `role="オペレーター"` のように、あらかじめ値(デフォルト値)を持たせておき、
  省略可能にした引数を**デフォルト引数**と呼ぶ
- デフォルト引数は、位置引数より**後ろ**に書く必要がある

### 3.4 可変長引数(`*args`)

「何個の値が渡されるか分からない」ときに使うのが可変長引数です。
引数名の前に `*` を付けると、渡された値がすべて**タプル**としてまとめられます。

```python
def total(*numbers):
    return sum(numbers)

total(1, 2, 3)       # numbers は (1, 2, 3) というタプルになる -> 6
total(10)             # numbers は (10,) -> 10
total()               # numbers は () -> 0
```

サーバー監視で「何台分のCPU使用率が渡されるか分からないが、まとめて平均を
計算したい」といった場面でとても便利です。

(参考: `**kwargs` という書き方もありますが、これはキーワード引数を辞書として
まとめる仕組みで、本章では扱いません。)

### 3.5 複数ファイルへのモジュール分割とimport

Pythonでは、1つの `.py` ファイルのことを**モジュール**と呼びます。
別のファイルにある関数は、`import` を使って読み込むことができます。

たとえば `exercises/utils.py` に次のような関数があるとします。

```python
# exercises/utils.py
def celsius_to_status(temp):
    ...
```

これを別のファイル `exercises/exercise3.py` から使うには、次のように
importします。

```python
# exercises/exercise3.py
from exercises.utils import celsius_to_status

def datacenter_temperature_report(temps):
    return [celsius_to_status(temp) for temp in temps]
```

`from パッケージ名.モジュール名 import 関数名` という書き方で、
特定の関数だけを取り出してimportできます。このように処理をファイルごとに
分けておくと、「温度判定のロジックだけ直したい」というときに
`utils.py` だけを見ればよくなり、見通しが良くなります。

(補足) このパックでは `exercises` フォルダの中に `__init__.py` という
空ファイルを置いています。これがあることで、Pythonは `exercises` フォルダを
1つの「パッケージ」として扱えるようになり、`exercises.utils` のような
形でimportできるようになります。

### 3.6 デコレーターの基礎

デコレーターは、「関数を受け取り、機能を追加した別の関数を返す関数」です。
`@デコレーター名` という書き方で、既存の関数に処理を追加できます。

```python
import functools
import time

def measure_time(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"[実行時間] {func.__name__}: {elapsed:.3f}秒")
        return result
    return wrapper

@measure_time
def slow_task():
    time.sleep(0.2)
    return "done"

slow_task()
# 標準出力に "[実行時間] slow_task: 0.200秒" のように表示され、
# slow_task() の戻り値("done")はそのまま返る
```

`@measure_time` を関数の上に書くと、それだけで「実行前後の時刻を測って
printする」という処理が自動的に追加されます。元の関数の中身は一切
変更していません。これが「処理の前後に共通処理をかぶせる」デコレーターの
考え方です。

`functools.wraps(func)` は、ラップ後の関数(`wrapper`)が元の関数の
`__name__` などの情報を引き継ぐためのおまじないです。これを付けないと、
デバッグ時に関数名が `wrapper` と表示されてしまい、原因調査がしづらく
なります。忘れずに書く習慣をつけましょう。
